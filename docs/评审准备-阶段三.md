## 一、评审议题清单

### 1.1 产品侧需向团队说明的内容

| 议题 | 说明 | 负责 |
|------|------|------|
| 需求背景 | 新萧山人的方言障碍；萧山话正在被普通话同化 | 产品 |
| 核心假设 | "场景化学习 + AI 纠音"能解决方言学习痛点 | 产品 |
| MVP 范围 | 6 大场景 + AI 评分 + 闯关 + 基础游戏化 | 产品 |
| 验收标准 | 首次学习完成率 > 60%、次日留存 > 30%、AI 使用率 > 50% | 产品 |

### 1.2 技术评审重点

| 议题 | 关键决策 | 待确认 |
|------|---------|--------|
| AI 评分方案 | DTW+MFCC 规则评分（自研） | 准确率待真实录音验证 |
| 录音接口 | 小程序 RecorderManager，mp3/16kHz/15s | 不支持流式，需录完上传 |
| 标准音 | 萧山城厢口音 | 需在课程中标注 |
| 后端架构 | Python FastAPI + MySQL | 部署方案待定 |
| 数据模型 | 9 张表（User/Scene/Sentence/...） | 需评审字段完整性 |

### 1.3 设计评审重点

| 议题 | 说明 |
|------|------|
| 页面清单 | 7 个页面（启动/登录/首页/场景/学习/记录/成就） |
| 交互边界 | 录音按钮状态机、评分弹窗、场景锁定 |
| 设计验收点 | 各页面 UI 规范、动画、Toast 文案 |

## 二、关键依赖与风险点

| 风险 | 等级 | 缓解措施 |
|------|------|-----------|
| AI 评分准确率不足（模拟音频分差仅 2-3 分） | 🟡 中 | 收集真实录音校准；预留 V1.1 深度学习方案 |
| 发音人未招募（用户暂未启动） | 🟡 中 | 开发可与语料编写并行；MVP 上线前必须完成录制 |
| 标准音争议（萧山内部口音差异） | 🟢 低 | 已定城厢口音，课程标注来源 |
| 小程序录音真机调试限制 | 🟢 低 | 提前准备真机测试计划 |
| 微信登录接口变更 | 🟢 低 | 关注微信开放社区公告 |

---

## 三、待确认问题（传递自阶段二）

1. **AI 评分准确率阈值**：MVP 可接受的最低准确率是多少？是否需要人工评分兜底？
2. **后端部署**：微信云托管 vs 腾讯云 CVM vs 容器服务？
3. **数据库选型**：MySQL vs PostgreSQL？是否需要 Redis 缓存学习记录？
4. **语料录制排期**：发音人招募何时启动？是否阻塞 MVP 上线？
5. **设计资源**：UI 设计由谁负责？是否有设计规范？
