## 一、需求概要

### 1.1 产品定位与一句话描述

**产品名称（暂定）**：「萧山话学堂」-- 面向新萧山人的萧山方言AI学习微信小程序。

**一句话描述**：一款专为"新萧山人"打造的微信小程序，通过"场景化日常用语学习 + AI语音识别纠音"，帮助外地人快速掌握实用萧山话，打破方言壁垒，融入本地生活。

**产品定位关键词**：实用、轻量、AI驱动、场景化、社交传播。

### 1.2 目标用户画像

**核心用户群体：新萧山人**

"新萧山人"是指因工作、婚嫁、求学、经商等原因来到萧山长期生活的外地人。萧山作为杭州的重要副城，近年来人口流入显著。据萧山日报2024年报道，萧山部分社区外来人口占比超过60%（如某社区近17000人中，外来人口过万）。

**用户细分：**

| 细分类型 | 典型特征 | 核心动机 | 预估占比 |
|---------|---------|---------|---------|
| **职场融入型** | 25-40岁，在萧山企业/政府部门工作 | 与本地同事、客户更好沟通，提升职场亲和力 | 45% |
| **婚嫁融入型** | 22-35岁，因婚嫁来到萧山 | 与伴侣家人（尤其是长辈）沟通，融入家庭生活 | 30% |
| **生活服务型** | 30-55岁，在萧山经营小店或从事服务业 | 与本地顾客日常交流，提升服务体验和客源 | 15% |
| **文化认同型** | 20-40岁，对吴语文化有兴趣的知识青年 | 了解萧山地域文化，获得身份认同感 | 10% |

**用户核心特征：**
- **语言基础**：会普通话，完全不懂萧山话（零基础），多数无吴语方言背景
- **学习时间**：碎片化，通勤、午休、睡前等短时段为主
- **技术习惯**：微信重度用户，习惯小程序形态，对下载独立App有抵触
- **学习痛点**：
  - 没有系统化的学习渠道（不像粤语有大量教材和课程）
  - 萧山话语音系统复杂（34个声母、47个韵母、8个声调），自学困难
  - 缺乏实践场景和反馈机制
  - 本地人日常交流中夹杂方言，听不懂产生隔阂感

### 1.3 核心价值主张

| 价值维度 | 具体描述 |
|---------|---------|
| **低门槛** | 微信小程序即开即用，无需下载安装，降低尝试成本 |
| **真场景** | 按"买菜、看病、坐车、办事"等真实场景组织内容，学了就能用 |
| **AI纠音** | 语音识别+AI评分，解决方言发音无反馈的核心痛点 |
| **游戏化** | 参考多邻国等产品机制，碎片化闯关学习，降低心理负担 |
| **社交裂变** | 微信生态内天然适合分享和传播，用户可邀请朋友一起学 |

## 二、用户场景与痛点分析

### 场景一：菜市场买菜，听不懂摊主报价

**用户故事**：小王来萧山工作一年，周末去本地菜市场买菜。摊主阿姨用萧山话报价"五块二"，小王完全听不懂，反复确认后阿姨露出不耐烦的表情。小王感到尴尬和被排斥。

**痛点分析**：
- 菜市场、街边小店等生活场景中，本地人习惯用方言交流
- 数字、重量单位、常见菜名等基础词汇不懂，造成沟通障碍
- 外地人容易被"识别"出来，产生"外地人"标签感

**现有解决方案及不足**：
- 用手比划/写字：效率低，场景受限
- 去超市购物（普通话环境）：失去菜市场的价格优势和烟火气
- 请教本地朋友：不系统，难以持续

---

### 场景二：过年去对象家，听不懂长辈聊天

**用户故事**：小李因婚嫁来到萧山，第一次去婆婆家过年。饭桌上亲戚们全程用萧山话聊天，小李只能微笑点头，完全无法参与。婆婆偶尔用普通话问她几句，让她感到被"特殊照顾"的尴尬。

**痛点分析**：
- 家庭聚会中萧山话是主要交流语言，尤其是中老年人
- 无法理解幽默、笑话和闲聊内容，情感上被边缘化
- 长期无法融入家庭交流，影响亲密关系建立
- 婆媳/翁婿关系中的方言障碍是隐性痛点

**现有解决方案及不足**：
- 让伴侣当翻译：不现实且影响家庭氛围
- 被动等待对方切换普通话：被动且可能让对方感到不便
- 临时学几句：不成体系，效果有限

---

### 场景三：在医院/办事大厅，听不懂工作人员的方言指引

**用户故事**：小张去萧山某社区卫生服务中心看病，挂号窗口的工作人员用带萧山话口音的普通话指引她去"二楼东边"，但因为夹杂方言词汇，小张没听清，走错了楼层。

**痛点分析**：
- 公共服务场景中，部分中老年工作人员习惯使用方言
- 方向指引、流程说明等关键信息听不懂，可能耽误正事
- 银行、医院、社区服务中心等场所方言使用率高

**现有解决方案及不足**：
- 多问几遍：不好意思反复询问
- 找年轻工作人员：不总是可行
- 线上办理替代线下：许多服务仍需线下

---

### 场景四：本地同事聚会，无法参与方言闲聊

**用户故事**：小陈在萧山一家本地企业工作，部门聚餐时同事们用萧山话聊八卦、开玩笑，小陈全程插不上嘴，只能默默吃饭。同事们切换到普通话时话题往往已经结束。

**痛点分析**：
- 职场社交中方言是"圈内人"标志
- 无法参与轻松话题影响同事关系建立
- 长期被排除在非正式沟通之外，影响职场发展

**现有解决方案及不足**：
- 等待同事切换普通话：被动且滞后
- 主动发起普通话话题：显得刻意

---

### 场景五：想学说两句但不知道从哪学、发音对不对

**用户故事**：小刘来萧山两年了，一直想学萧山话。他在抖音上刷到过几个萧山话教学短视频，但零散不成体系。他尝试模仿跟读，但不知道自己发音对不对，也没有人纠正。

**痛点分析**：
- 萧山话学习资源极其匮乏，不像粤语、上海话有成熟的学习产品
- 自学无法获得发音反馈，容易形成错误发音习惯
- 缺乏系统的学习路径和进度管理
- 吴语浊音声母、入声等对北方方言区用户来说极难掌握

**现有解决方案及不足**：
- 抖音/喜马拉雅零散内容：不系统、无法互动、无反馈
- 方言通App：萧山话覆盖极弱，内容少
- 请教本地朋友：朋友不一定有耐心和时间系统教学

## 三、竞品分析

### 3.1 直接竞品：方言通App

**产品概况**：方言通由梅州市拓思信息科技有限公司开发，覆盖全国数十种方言（粤语、闽南语、吴语、四川话、客家话等），是市场上最知名的方言学习产品。

**核心功能**：
- 海量方言库：常用词句发音，由地道当地人录制
- 趣味录音对比：录制发音与标准音轨波形对比
- 地道音频课程：编排的方言学习课程与文化故事
- 方言社区/词典/测试等辅助功能

**优势**：
- 覆盖方言种类多
- 录音对比功能设计直观
- 已有一定用户基础和口碑

**针对萧山话的不足（我们的机会点）**：
| 维度 | 方言通App | 我们的机会 |
|------|----------|----------|
| 萧山话内容深度 | 浅层覆盖，仅少量基础词句 | 深度聚焦萧山话，做精做透 |
| 学习路径 | 无系统化学习路径，以查词为主 | 按CEFR思路设计分级学习路径 |
| AI纠音 | 仅波形对比，无智能评分和纠错 | 引入AI语音识别+评分，提供针对性反馈 |
| 场景化 | 按词汇表组织，非真实场景 | 按"买菜、看病、办事"等真实场景组织 |
| 用户定位 | 泛方言爱好者 | 精准定位"新萧山人"实际需求 |
| 传播渠道 | 独立App，获客成本高 | 微信小程序，天然社交裂变 |
| 游戏化 | 较弱 | 参考多邻国设计连胜、排行榜、闯关机制 |

### 3.2 标杆参考：多邻国（Duolingo）

**值得借鉴的产品机制**：

1. **学习路径可视化**：清晰的闯关地图，用户始终知道自己在哪、目标在哪
2. **碎片化学习**：每节课3-5分钟，降低心理负担
3. **在实践中学习（Learn by Doing）**：从第一课就开始互动答题，而非先讲理论
4. **游戏化三要素（PBL）**：
   - Points（积分/经验值）
   - Badges（徽章/成就）
   - Leaderboard（排行榜）
5. **连胜机制（Streak）**：每天打卡保持连胜，利用避祸心理驱动留存
6. **个性化难度**：根据答题正确率动态调整题目难度（Desirable Difficulty）
7. **即时正向反馈**：每完成一个练习都有鼓励动画和音效

**多邻国模式在方言学习中的适配性**：
- 方言学习的目标不是"流利对话"而是"日常沟通"，更适合碎片化学习
- 方言更依赖听说（而非读写），AI语音交互的价值更大
- 方言学习的社会性更强（为融入本地），社区/社交功能权重更高

### 3.3 其他可参考产品

| 产品 | 可借鉴点 |
|------|---------|
| 沪江开心词场 | 闯关背词模式，游戏化PK |
| 英语流利说 | AI语音评分引擎，发音纠正 |
| 喜马拉雅方言频道 | 音频内容组织方式 |
| 小红书方言话题 | UGC内容传播模式 |

### 3.4 我们的差异化定位

**一句话总结**：做方言学习领域的"萧山话版多邻国"--深度垂直 + AI驱动 + 场景化 + 微信生态。

**核心差异化**：
1. **深度而非广度**：只做萧山话，做到最精最深
2. **AI驱动而非纯内容**：引入语音识别评分，提供实时发音反馈
3. **场景闭环而非词汇堆砌**：按真实生活场景组织，学完就能用
4. **微信原生而非独立App**：借助微信生态降低获客成本、促进社交裂变

## 四、MVP功能规划

### P0（必须有）-- 核心闭环功能

| 功能模块 | 功能描述 | 优先级理由 |
|---------|---------|----------|
| **场景化课程** | 按"买菜"、"看病"、"坐车"、"办事"、"家庭交流"、"职场寒暄"6大场景组织课程，每个场景5-10句核心用语 | 核心价值载体 |
| **标准发音播放** | 每条语句配备由地道萧山发音人录制的高质量音频 | 学习的基础 |
| **AI语音识别评分** | 用户跟读后，AI对发音进行打分（0-100分），标注发音不准的音节 | 核心差异化功能 |
| **闯关学习路径** | 线性课程路径，完成前一课解锁后一课，进度可视化 | 学习路径引导 |
| **基础游戏化** | 每日打卡、学习积分、简单成就徽章 | 初期留存 |
| **个人学习记录** | 学习天数、已学语句数、平均得分等基础统计 | 用户成就感知 |

**MVP核心闭环**：用户打开小程序 -> 选择场景 -> 听标准发音 -> 跟读录音 -> AI评分反馈 -> 获得积分 -> 解锁下一课 -> 每日打卡提醒 -> 回来继续学习。

### P1（应该有）-- 增强体验

| 功能模块 | 功能描述 | 优先级理由 |
|---------|---------|----------|
| **发音对比回放** | 用户可以回放自己的录音与标准发音对比 | 强化纠音效果 |
| **连胜机制（Streak）** | 连续学习天数统计，连胜火焰动画 | 参考多邻国，提升留存 |
| **排行榜** | 好友排行榜 + 全站排行榜（周榜） | 社交激励 |
| **学习提醒** | 微信服务通知/模板消息推送学习提醒 | 召回手段 |
| **难度分级** | 初级（生存用语）/ 中级（日常交流）/ 高级（地道表达） | 满足不同阶段用户 |
| **收藏夹** | 收藏常用语句，方便复习 | 个性化学习 |
| **文化小知识** | 每课附带一条萧山文化知识卡片（如萧山萝卜干、湘湖文化等） | 增强文化认同 |
| **邀请好友** | 微信分享卡片，邀请朋友一起学 | 社交裂变 |

### P2（可以有）-- 锦上添花

| 功能模块 | 功能描述 | 优先级理由 |
|---------|---------|----------|
| **AI对话练习** | 模拟菜市场、医院等场景，与AI进行方言对话 | 技术复杂度高 |
| **学习社区** | 用户可发帖交流学习心得、分享萧山生活经验 | 社区运营成本高 |
| **线下活动** | 组织线下萧山话角/交流会 | 运营重 |
| **方言PK对战** | 实时对战，比拼发音准确度 | 需要较大用户基数 |
| **自定义场景** | 用户可提交想学的场景和语句 | 需求验证后再做 |
| **多方言版本** | 扩展到临绍小片其他方言（绍兴话、诸暨话等） | 远期扩展 |

## 五、语料资源获取方案

### 5.1 语料内容规划

按照"从生存到生活、从实用到文化"的原则，分场景规划语料：

**第一阶段：生存用语（约50句）**

| 场景 | 典型语句（举例） | 数量 |
|------|----------------|------|
| 数字与价格 | "两块五"、"多少钱"、"太贵了"、"便宜点" | 10句 |
| 菜市场 | "这个菜新鲜吗"、"来两斤"、"有葱吗" | 10句 |
| 交通出行 | "去人民路怎么走"、"在这里下车"、"多少钱一位" | 10句 |
| 看病就医 | "挂个号"、"头疼"、"在哪里取药" | 10句 |
| 办事大厅 | "在几楼"、"要排队吗"、"带什么材料" | 10句 |

**第二阶段：社交用语（约50句）**

| 场景 | 典型语句（举例） | 数量 |
|------|----------------|------|
| 家庭交流 | "饭吃了没"、"今天菜不错"、"你身体好吗" | 10句 |
| 职场寒暄 | "今天忙吗"、"吃了吗"、"周末去哪" | 10句 |
| 邻里问候 | "你住几楼"、"你家小孩多大了" | 10句 |
| 饮食相关 | "这个好吃"、"太咸了"、"再来一碗" | 10句 |
| 天气时间 | "今天真热"、"快下雨了"、"几点了" | 10句 |

**第三阶段：地道表达（约50句）**

| 场景 | 典型语句（举例） | 数量 |
|------|----------------|------|
| 俗语谚语 | 萧山本地特色谚语、歇后语 | 15句 |
| 幽默调侃 | 本地人常用的调侃、玩笑话 | 15句 |
| 文化特色 | 与萧山历史文化相关的表达 | 20句 |

**语料筛选原则**：
1. **高频优先**：选择本地人日常使用频率最高的表达
2. **实用导向**：学了就能在真实场景中用上
3. **文化代表性**：包含萧山方言特色词汇和语法结构（如"饭吃了吗"的宾动结构）
4. **难度递进**：从短句到长句，从简单音节到包含浊音/入声的复杂发音

### 5.2 发音人招募方案

**发音人要求**：
- 萧山本地出生，在萧山生活30年以上
- 发音纯正，无明显外地口音影响
- 年龄建议50-65岁（方言保存更完整，受普通话影响较小）
- 口齿清晰，表达流畅

**招募渠道**：

| 渠道 | 方式 | 预估效率 |
|------|------|---------|
| 萧山本地社区/街道办 | 通过社区居委会发布招募通知 | 高 |
| 萧山老年大学 | 联系老年大学推荐合适人选 | 中 |
| 萧山本地公众号/论坛 | 发布招募文章 | 中 |
| 方言研究机构/高校 | 联系浙江大学、杭州师范大学语言学系 | 低（学术合作） |
| 本地社群推荐 | 通过朋友圈、微信群传播 | 中高 |

**激励方式**：
- 按句付费（参考市场价：5-10元/句，含多次录制）
- 署名致谢（满足文化传承的荣誉感）
- 赠送小程序终身会员

**预计需要**：2-3名发音人（男女各1名，备选1名），确保音色多样性。

### 5.3 录制与标注流程建议

**录制流程**：

```
1. 语料准备
   - 编写标准语料文本（含汉字 + 吴语拼音标注）
   - 请语言顾问审核确认发音准确性
   
2. 录音环境
   - 安静室内环境（背景噪音 < -60dB）
   - 设备：专业录音麦克风 + 音频接口（或高品质USB麦克风）
   - 采样率：44.1kHz/48kHz，16bit/24bit
   - 格式：WAV（无损）+ MP3（发布用）
   
3. 录制执行
   - 每句录制3-5遍，选取最佳版本
   - 正常语速 + 慢速版（供初学者跟读）
   - 发音人佩戴监听耳机，实时检查录音质量
   
4. 后期处理
   - 降噪处理（保留自然音色）
   - 响度标准化
   - 裁剪静音段
   - 文件命名规范：scene_level_id_speaker.wav
```

**标注规范**：

| 标注维度 | 内容 | 用途 |
|---------|------|------|
| 文本标注 | 汉字原文、吴语拼音、普通话释义 | 前端展示、搜索 |
| 音素标注 | 声母、韵母、声调标注 | AI评分模型训练 |
| 场景标签 | 所属场景、难度等级 | 课程组织 |
| 关键词标注 | 核心词汇提取 | 词汇学习模块 |
| 语法标注 | 特殊语法结构说明（如宾动结构） | 知识卡片展示 |

**质量检查**：
- 每批次录音随机抽查20%，由萧山本地人评审发音准确性
- 音频技术指标检测（响度、信噪比、截幅等）

## 七、待确认问题清单

以下问题需要在进入开发阶段前进一步确认，按优先级排序：

### 高优先级（影响MVP设计）

1. **AI语音评测技术选型**：
   - 第三方API方案（腾讯云智聆、百度语音评测、讯飞语音评测）是否支持吴语/萧山话评测？
   - 如果不支持，自研模型的最低可行方案是什么？（例如：用普通话模型+萧山话发音规则做后处理评分）
   - **建议**：先调研腾讯云智聆是否支持自定义发音词典，以及微信同声传译插件的方言支持情况。

2. **微信小程序录音接口限制**：
   - 小程序 `RecorderManager` 的录音格式和时长限制是否满足需求？
   - 是否支持实时语音流传输（流式识别），还是只能录完再上传？
   - **建议**：技术预研阶段优先验证录音+上传+评分的完整链路。

3. **发音人合作意愿**：
   - 能否找到2-3名符合条件的萧山发音人？
   - 对方是否愿意参与商业项目？合作条件是什么？
   - **建议**：MVP开发前先通过社区渠道完成发音人招募。

4. **萧山方言的"标准音"问题**：
   - 萧山内部存在地域差异（城厢、临浦、瓜沥口音不同），以哪个区域为标准？
   - 是否在课程中注明口音来源？
   - **建议**：以城厢口音为标准（参考《萧山市志》），其他口音作为补充。

### 中优先级（影响产品方向）

5. **目标用户触达渠道**：
   - 新萧山人主要通过哪些渠道获取信息？（本地公众号、社区群、朋友推荐？）
   - 第一批种子用户从哪里获取？
   - **建议**：MVP上线前与萧山本地生活类公众号洽谈合作推广。

6. **与萧山官方/社区的合作可能性**：
   - 能否与萧山文旅局、社区街道办建立合作？
   - 能否获得浙江省方言资源保护工作的政策支持？
   - **建议**：完成MVP后寻求官方背书，增加权威性和传播力。

7. **商业化方向**：
   - 纯免费+广告？基础免费+VIP订阅？一次性付费？
   - 目标用户（新萧山人）的付费意愿如何？
   - **建议**：MVP阶段全免费验证需求，第二期再测试付费转化。

8. **内容版权归属**：
   - 语料文本、音频录音的知识产权归属如何界定？
   - 发音人的录制内容是否可以商用？
   - **建议**：在发音人合作协议中明确版权归属和商用授权。

### 低优先级（远期考虑）

9. **扩展到其他方言的可行性**：萧山话验证成功后，是否扩展到绍兴话、诸暨话等临绍小片其他方言？

10. **AI模型迭代路径**：积累足够用户语音数据后，是否自研专门的萧山话语音识别模型？

11. **与萧山学校/教育机构合作**：能否将小程序引入萧山本地学校的方言教育课程？

## 八、数据指标建议

### 8.1 北极星指标

**主北极星指标：每周活跃学习用户数（WAU，Weekly Active Learners）**

选择理由：
- 方言学习是低频但持续的需求，周活跃比日活跃更能反映真实使用情况
- 直接反映产品的核心价值交付（帮助用户持续学习）
- 与产品阶段匹配：MVP期关注质量，成长期关注规模

**辅助北极星指标：每周完成课程数（Lessons Completed per Week）**

选择理由：
- 反映学习深度，不仅是"来过"而是"学了"
- 可以拆解到每个用户的学习效率

### 8.2 关键过程指标（按AARRR模型）

| 阶段 | 指标 | 目标（MVP期） | 目标（成长期） |
|------|------|-------------|-------------|
| **Acquisition（获客）** | 小程序日新增用户数 | 10-20人/天 | 50-100人/天 |
| | 用户来源渠道分布 | 微信分享 > 搜索 > 公众号 | - |
| | 获客成本（如有付费推广） | 0（纯自然增长） | < 2元/用户 |
| **Activation（激活）** | 注册转化率 | > 80% | > 90% |
| | 首次学习完成率 | > 60% | > 75% |
| | 首次AI评分触发率 | > 50% | > 80% |
| **Retention（留存）** | 次日留存 | > 30% | > 40% |
| | 7日留存 | > 15% | > 25% |
| | 30日留存 | > 10% | > 15% |
| | 连续学习3天以上用户占比 | > 20% | > 35% |
| **Revenue（收入）** | 付费转化率（如有付费功能） | N/A（MVP免费） | > 3% |
| | ARPU（每用户平均收入） | N/A | > 5元/月 |
| **Referral（传播）** | 分享率（分享用户/活跃用户） | > 10% | > 20% |
| | K因子（每个用户带来新用户数） | > 0.3 | > 0.5 |
| | 邀请好友成功率 | > 15% | > 25% |

### 8.3 学习质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 平均学习时长 | 每次学习的平均时长 | 3-5分钟 |
| 课程完成率 | 完成当前场景全部课程的用户比例 | > 40% |
| 发音平均得分 | 所有用户AI评分的平均值 | > 65分 |
| 发音得分提升 | 同一用户学习前后的发音得分变化 | +15分以上 |
| 复习率 | 用户主动回看已学内容的比例 | > 25% |
| 收藏使用率 | 使用收藏功能的用户占比 | > 20% |

### 8.4 技术性能指标

| 指标 | 目标 |
|------|------|
| AI评分响应时间 | < 3秒（含录音上传+识别+评分+返回） |
| 录音上传成功率 | > 98% |
| 小程序冷启动时间 | < 2秒 |
| 页面加载时间 | < 1秒 |
| 音频播放失败率 | < 1% |

### 8.5 MVP验证期的核心关注指标（Top 5）

在MVP阶段，我们最需要验证的是**价值假设**和**增长假设**，因此重点看这5个指标：

1. **首次学习完成率 > 60%**：验证用户是否真的愿意"学方言"
2. **AI评分功能使用率 > 50%**：验证AI纠音是否解决核心痛点
3. **次日留存 > 30%**：验证产品是否有持续吸引力
4. **分享率 > 10%**：验证用户是否愿意主动传播
5. **NPS净推荐值 > 30**：通过问卷调研用户的推荐意愿

## 附录

### A. 萧山方言关键语音特点（对产品设计的影响）

| 语音特点 | 描述 | 对产品的影响 |
|---------|------|------------|
| 浊音声母 | 保留古汉语浊音（如b/d/g对应的浊音），普通话已消失 | AI识别需区分清浊对立，发音提示需特别标注 |
| 入声 | 以-p/-t/-k收尾的短促音 | 发音示范需突出入声特点，评分模型需单独处理 |
| 8个声调 | 平上去入各分阴阳，比普通话多4个 | 声调教学需专门设计，建议用"五度标记法"可视化 |
| 连读变调 | 多字组合时声调发生变化 | 需按"词/短语"而非"单字"为单位教学 |
| 鼻化韵 | 韵母带鼻音色彩 | 发音示范需清晰区分口音和鼻化音 |
| 宾动结构 | 如"饭吃了吗"而非"吃饭了吗" | 语法知识卡片需特别说明，避免用户困惑 |
