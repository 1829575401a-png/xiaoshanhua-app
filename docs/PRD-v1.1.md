## 2. 背景与目标

### 2.1 项目背景

萧山作为杭州重要副城，外来人口持续增长，部分社区外来人口占比超过 60%。新萧山人在日常生活、家庭交流、职场社交中频繁遇到方言障碍。与此同时：

- 萧山话属于吴语太湖片，保留古汉语浊音声母、入声和 8 个声调，自学门槛极高；
- 萧山话正在加速"共同语化"（被普通话同化），方言保护和传承具有紧迫性；
- 萧山已被列为浙江省方言资源保护工作调查点，政策层面有明确支持；
- 市场上缺乏专门针对萧山话的系统化学习产品，「方言通」App 仅浅层覆盖。

### 2.2 产品目标（MVP 阶段）

| 维度 | 目标 |
|------|------|
| **用户价值** | 让新萧山人能在碎片时间学会 50+ 句萧山话日常用语，获得 AI 发音反馈 |
| **核心验证** | 验证"场景化方言学习 + AI 纠音"模式是否能满足新萧山人需求 |
| **用户规模** | MVP 上线后 1 个月内获取 100 名活跃种子用户 |
| **关键指标** | 首次学习完成率 > 60%，次日留存 > 30%，AI 评分使用率 > 50% |

### 2.3 产品范围

**本次 MVP 范围**：覆盖 P0 功能（6 大场景课程 + AI 语音评分 + 闯关路径 + 基础游戏化 + 个人学习记录）。

**不在此版本范围**：发音对比回放、连胜机制、排行榜、学习提醒、难度分级、收藏夹、文化小知识、邀请好友（P1）；AI 对话练习、学习社区、线下活动（P2）。

## 5. 核心流程说明

### 5.1 用户首次使用主流程

```
用户打开小程序
    │
    ▼
[启动页] ── 展示产品名称 + 一句话介绍（2秒自动跳转或点击跳过）
    │
    ▼
[微信授权登录] ── 用户点击「微信一键登录」授权头像昵称
    │
    ▼
[学习首页] ── 展示课程地图 + 学习数据概览
    │
    ▼
[选择场景] ── 用户点击第一个可用的场景卡片（其余灰色锁定）
    │
    ▼
[课程详情页] ── 展示当前句子的汉字、拼音、释义 + 播放标准发音
    │
    ▼
[录音跟读] ── 用户长按/点击录音按钮，跟读当前句子
    │
    ▼
[AI评分结果] ── 展示得分（0-100）+ 发音反馈 + 鼓励文案
    │
    ▼
[下一句 / 完成课程] ── 继续下一句，或完成该场景全部句子
    │
    ▼
[解锁下一场景] ── 返回课程地图，新场景已解锁
```

### 5.2 用户回访学习流程

```
用户打开小程序（已登录）
    │
    ▼
[学习首页] ── 展示课程进度 + 连续打卡天数 + 今日是否已打卡
    │
    ▼
[继续学习] ── 自动定位到上次学习位置，继续闯关
    │
    ▼
[学习循环] ── 听 → 跟读 → 评分 → 下一句
```

### 5.3 AI 语音评分流程

```
用户点击录音按钮
    │
    ▼
系统检查麦克风权限 ── 未授权 → 引导用户开启权限
    │ 已授权
    ▼
开始录音 ── 显示录音动画 + 计时（最长15秒）
    │
    ▼
用户松开按钮 / 自动停止
    │
    ▼
上传音频到后端 → 调用 AI 语音评测服务
    │
    ▼
返回评分结果（< 3秒内）
    │
    ├── 得分 ≥ 80：展示绿色高分 + 鼓励文案
    ├── 得分 60-79：展示黄色中等分 + 标注薄弱音节
    └── 得分 < 60：展示红色低分 + 鼓励重试 + 标注薄弱音节
```

## 7. 功能需求详述（EARS 原则）

### 7.1 微信授权登录（F-10）

**Ubiquitous（始终满足的约束）**：
- The system shall 在用户首次打开小程序时展示登录页面
- The system shall 使用微信 `<button open-type="getPhoneNumber">` 或 `wx.getUserProfile` 获取用户信息
- The system shall 将用户 openid、头像、昵称持久化存储于后端数据库
- The system shall 在后续访问中自动识别已登录用户，跳过登录页

**Event-driven（事件触发）**：
- When 用户点击「微信一键登录」按钮，the system shall 调用微信授权接口获取用户信息
- When 授权成功，the system shall 创建或更新用户记录，并跳转至学习首页
- When 用户首次登录完成，the system shall 自动解锁第一个场景「菜市场」

**Unwanted（异常处理）**：
- If 用户拒绝授权，then the system shall 停留在登录页，并展示 Toast「需要授权才能开始学习哦」
- If 微信授权接口调用失败（网络异常/超时），then the system shall 展示「登录失败，请检查网络后重试」并提供重试按钮
- If 后端创建用户记录失败，then the system shall 记录错误日志，并展示「系统繁忙，请稍后再试」

**State-driven（状态相关）**：
- While 用户处于已登录状态，the system shall 不再展示登录页，直接进入学习首页

---

### 7.2 场景化课程展示（F-01）

**Ubiquitous**：
- The system shall 在首页以卡片列表形式展示 6 个场景课程
- The system shall 每个场景包含 5-10 句萧山话学习内容（MVP 阶段共约 50 句）
- The system shall 为每个场景卡片展示场景名称、场景图标、学习进度百分比
- The system shall 按以下顺序排列场景：菜市场 → 看病就医 → 交通出行 → 办事大厅 → 家庭交流 → 职场寒暄

**Event-driven**：
- When 用户完成当前场景所有句子的首次学习，the system shall 自动解锁下一个场景
- When 用户点击已解锁的场景卡片，the system shall 跳转至场景课程页
- When 用户点击未解锁的场景卡片，the system shall 展示 Toast「先完成上一场景吧～」

**State-driven**：
- While 某场景被锁定，the system shall 展示灰色锁定图标，并禁用点击跳转
- While 某场景已解锁但未完成，the system shall 展示进度条和完成百分比
- While 某场景已完成全部学习，the system shall 展示「已完成」标记 + ✅ 图标

---

### 7.3 标准发音播放（F-02）

**Ubiquitous**：
- The system shall 为每句学习内容提供由萧山本地发音人录制的标准音频
- The system shall 发音人以萧山城厢口音为标准（经调研确认，城厢话为萧山代表方言）
- The system shall 在学习详情页展示圆形播放按钮
- The system shall 支持点击播放和暂停

**Event-driven**：
- When 用户点击播放按钮，the system shall 开始播放标准发音音频
- When 音频开始播放，the system shall 播放按钮切换为暂停图标并展示脉冲动画
- When 音频播放结束，the system shall 自动恢复为播放图标

**Unwanted**：
- If 音频加载失败，then the system shall 展示 Toast「音频加载失败，请重试」并提供重试按钮
- If 用户在播放过程中退出页面，then the system shall 停止音频播放

**State-driven**：
- While 音频正在加载，the system shall 播放按钮展示加载动画（旋转图标）

### 7.4 AI 语音跟读评分（F-03）

> **技术决策**：经调研，腾讯云智聆、讯飞、百度语音评测均不支持吴语方言评测。MVP 阶段采用自研 DTW+MFCC 声学特征规则评分方案（详见附录 B）。该方案已通过 PoC 验证，能有效区分不同质量的发音，单次评分 < 0.5s。

**Ubiquitous**：
- The system shall 在学习详情页提供录音跟读功能
- The system shall 支持长按录音、松开结束的交互方式
- The system shall 最长录音时长为 15 秒
- The system shall 录音格式为 mp3，采样率 16000Hz，单声道（微信小程序 RecorderManager 完全支持）
- The system shall 录音结束后将音频上传至后端，调用 DTW+MFCC 评分服务
- The system shall 在 3 秒内返回评分结果
- The system shall 评分范围为 0-100 分

**Event-driven**：
- When 用户按下录音按钮，the system shall 请求麦克风权限（如未授权）
- When 用户开始录音，the system shall 展示录音波形动画和计时器
- When 用户松开录音按钮或达到 15 秒上限，the system shall 停止录音并上传
- When AI 评分结果返回，the system shall 以弹窗形式展示得分、反馈文案和薄弱音节标注
- When 用户点击「再试一次」，the system shall 关闭弹窗并重置录音状态
- When 用户点击「下一句」，the system shall 保存本次得分并跳转至下一句学习页

**Unwanted**：
- If 用户未授权麦克风权限，then the system shall 引导用户前往「设置 → 微信 → 麦克风」开启权限
- If 录音时长不足 1 秒，then the system shall 展示 Toast「录音太短，请重新录制」且不上传
- If 音频上传失败，then the system shall 展示 Toast「上传失败，请检查网络后重试」并保留录音按钮可用
- If AI 评分接口超时（> 5 秒），then the system shall 展示 Toast「评分服务繁忙，请稍后再试」
- If AI 评分接口返回异常结果（如负数或 null），then the system shall 记录错误日志并展示通用提示「评分异常，请重试」

**State-driven**：
- While 录音进行中，the system shall 禁用播放按钮和「下一句」按钮
- While AI 评分计算中，the system shall 展示加载动画（「AI 正在评分...」）
- While 弹窗展示中，the system shall 禁止底层页面滚动

### 9.1 网络异常

| 场景 | 处理策略 |

| 小程序冷启动时无网络 | 展示离线提示页「当前无网络，请检查网络设置」，提供「重试」按钮 |

| 场景 | 处理策略 |
|------|---------|
| 麦克风权限未授权 | 录音前检测权限，未授权时引导用户前往系统设置开启 |

### 9.3 数据边界

| 场景 | 处理策略 |
|------|---------|
| 用户录音时长为 0（未说话） | 展示 Toast「未检测到声音，请重新录制」 |
| 用户录音时长 < 1 秒 | 展示 Toast「录音太短，请重新录制」 |
| 用户连续快速点击录音按钮 | 防抖处理，500ms 内仅响应一次 |

### 9.4 并发与状态冲突

| 场景 | 处理策略 |
|------|---------|
| 用户在 AI 评分返回前退出页面 | 评分结果静默保存，下次进入该句时展示上次得分 |
| 用户在录音中接听电话 | 录音自动取消，展示 Toast「录音已取消」 |
| 用户在音频播放中开始录音 | 自动停止音频播放，开始录音 |
| 多个设备同时登录同一账号 | 以最后操作的设备为准，学习进度实时同步 |

### 9.5 兼容性

| 场景 | 处理策略 |
|------|---------|
| iOS 微信版本过低（< 8.0） | 检测版本，展示提示「请升级微信至最新版本」 |

### B. 技术方案（四大问题决策结论）

#### B.1 AI 语音评测：DTW+MFCC 自研规则评分

**决策**：MVP 采用自研 DTW+MFCC 声学特征规则评分方案。

**背景**：经调研，腾讯云智聆（SOE）、讯飞语音评测、百度语音评测均**不支持吴语或任何中文方言**的发音评测，仅支持普通话和英文。

**技术路径**：

```
用户录音（mp3/16kHz）     标准发音（mp3/16kHz）
      │                         │
      ▼                         ▼
  librosa 加载音频          librosa 加载音频
      │                         │
      ▼                         ▼
  提取 39 维 MFCC           提取 39 维 MFCC
  (13 MFCC + Δ + ΔΔ)       (预计算存储)
      │                         │
      └────────┬────────────────┘
               ▼
        DTW 动态时间规整
        (fastdtw, euclidean)
               │
               ▼
         帧级余弦相似度
               │
               ▼
      分数映射 (0-100)
      score = 100 × mean_sim^1.5
               │
               ▼
       薄弱区域检测
       (相似度 < 20%分位)
```

**技术栈**：Python 后端 + `librosa`（音频处理）+ `fastdtw`（时序对齐）+ `numpy/scipy`（相似度计算）+ `FastAPI`（API 服务）

**PoC 验证结论**（2026-07-09）：
- ✅ DTW+MFCC 能有效区分不同质量的发音，排序正确性通过
- ✅ 薄弱区域检测可定位到音频中的偏差时间段
- ✅ 单次评分计算 < 0.5s，满足 < 3s 的需求
- ⚠️ 模拟音频的分数区分度偏窄（好发音 vs 差发音分差约 2-3 分），需用真实录音进一步验证和调参
- ⚠️ 待真实萧山话录音验证：MFCC 对浊音声母的区分能力、对 8 个声调的敏感度、与人工评分的相关系数（目标 > 0.7）

**升级路径（V1.1）**：当收集到 > 1000 条标注数据后，可升级为 `wav2vec 2.0` / `HuBERT` 微调方案，预期准确率提升至 80-85%。

#### B.2 录音接口：RecorderManager 完全满足

**配置**：`format: 'mp3'`, `sampleRate: 16000`, `numberOfChannels: 1`, `duration: 15000`, `encodeBitRate: 48000`

**关键限制**：小程序不支持实时音频流传输，只能录完再上传。总延迟约 4-8 秒（录音 2-5s + 上传 1-2s + 评分 0.5-1s），在可接受范围。

**调试注意**：微信开发者工具不支持录音测试，必须在真机上调试。

#### B.3 标准音选择：萧山城厢口音

**决策**：以萧山城厢口音为标准音。

**依据**：
- 萧山政府网《萧山方言简介》认定"代表萧山方言的是城厢镇语言"
- 吴语学堂《萧山方言拼音方案》基于城厢口音
- 《萧山市志》（2013）以城厢话为记录标准
